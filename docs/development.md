Local `forkDroidSession`, `compactDroidSession` and `rewindDroidSession` now share one replacement path. A connection owns the channel, dispatcher, ID allocator, turn lock and availability signal; each handle owns a lifecycle state and in-flight request count. Replacement rejects active turns, blocks new source-handle requests and drains existing ordinary requests before switching the CLI's active session. Successful attachment atomically retires the source and publishes a successor owned by the original scope. Failed attachment reloads the source; failed rollback or uncertain operation outcomes invalidate it. Compaction uses the reference 240-second exchange deadline; rewind and loading use 60 seconds.

Retirement is the linearization point, not a promise of atomic caller receipt. Cancellation delivered before commit is handled by the attachment/rollback path; cancellation arriving while masked may be delivered after a successful commit. The old handle then remains replaced, records its target ID and does not own a new process. The original scope still owns the connection. A review initially treated this as a transport handoff defect, then withdrew that finding after distinguishing committed-operation ambiguity from resource leakage. No additional successor registry or artificial pre-commit checkpoint was added.

Review did identify a real admission defect: cancellation of an ordinary mutating RPC could release its local lease while remote work remained pending, allowing replacement to cross it. The native regression failed with a peer trace of rename → fork → successor load. Ordinary request effects are now explicit: uncertain mutation outcomes invalidate under a mask before releasing their lease. The drain rechecks lifecycle state, and its error cleanup restores readiness only while still replacing. A further double-cancellation review tightened the classification/state-transition mask while leaving the RPC and interruption wait interruptible.

RPC response delivery is independent of queued notification dispatch. `synchronizeRpcEvents` adds an internal event-prefix boundary, acknowledged when the sole consumer advances past prior events; it sends no wire frame and does not join asynchronously spawned server-request workers. Startup/load operations include that boundary in their existing 60-second budget before exposing a handle. Four dispatcher tests cover reply-before-callback ordering, completion without another event, cancelled boundaries and terminal wakeup. Native replacement tests replay history on both successor and rollback loads.

The replacement peer retains saved session state and independent request traces. Gates use private temporary files; load/mutation gates complete a server-request response first so the initiating write is known to have released the channel writer before cancellation. The drain gate observes/rejects premature requests rather than masking them with serial processing; temporarily removing the drain check made its regression fail, after which the guard was restored. Tests require healthy cancelled loads to attempt and complete rollback, separately cover rollback cancellation and unknown mutating outcomes, and retain post-commit ownership checks. The standard `directory` package was added only as a direct test dependency for owned gate cleanup.

`test/ProcessSpec.hs` provides thirteen offline process-exchange checks. A private `--jsonl-peer` mode in the test executable provides a real child process, with a test-only PID handshake followed by protocol 1.205.0 fixtures. Checks cover acknowledgement, streamed deltas, explicit completion, byte-split UTF-8/coalesced frames, stderr backpressure, CRLF, malformed/non-object/invalid-UTF-8 frames, byte limits, EOF/truncation, callback failure and cancellation. Shutdown checks cover cooperative exit, ignored SIGTERM, nonpositive grace, natural-exit races, full-pipe writes and cancellation during the grace period. Each launched peer is checked for termination and reaping.

`withJsonLinesProcess limit grace config action` takes the frame-byte limit and then the SIGTERM grace in microseconds. It owns its pipes and child process, overrides configured stdio, and preserves the caller's other process settings. Cleanup sends SIGTERM, polls for exit during positive grace, then sends SIGKILL if the owned PID remains and reaps it before closing the pipes. Cancellation during grace also takes the force-and-reap path; asynchronous exceptions are deferred during that final step. There is no absolute kernel-exit deadline or descendant management. Callers must finish their send/receive threads before leaving the callback. Stderr is discarded and failures expose only fixed categories; framing/I/O errors must end the exchange. The low-level transport does not choose Droid arguments, attribution, authentication, retries or exit-code classification; `Factory.Droid` supplies scoped local startup separately.

The resistant-child regression failed against the preceding checkpoint after 5.02 seconds. A second regression, using repeated small frames rather than a single large write, exposed a buffered stdin flush that blocked `hClose` before escalation and replaced cancellation with a cleanup failure. Termination now precedes pipe closure, and `process`'s existing `ignoreSigPipe` helper suppresses only EPIPE when closing that terminated child's stdin. Unbuffered mode alone did not resolve the failure.

A five-second self-kill watchdog prevents leaked fixture processes when cleanup is broken; a separate two-second assertion prevents that watchdog from being mistaken for successful parent cleanup. The final thirteen-test group, including small and large full-pipe writes, passed thirty consecutive runs with four test workers and two GHC capabilities.

Repeated tests exposed an EOF cleanup race with the initially evaluated `typed-process` 0.2.13.0: cancellation of its exit waiter was followed by a second `waitForProcess` reporting no child. The final implementation uses one reaping path through `process`, without suppressing the failure. Thirty consecutive focused runs passed after this change.

`test/MetadataSpec.hs` adds 43 schema-backed checks for SDK metadata, version syntax, attribution branches, extension preservation and trace fields. `test/EnvelopeSpec.hs` adds 81 checks for complete envelopes, schema intersections, typed results, nullable IDs and overlapping response unions. The original process transcript now decodes full envelopes rather than only bare bodies.

`test/ProtocolSpec.hs` provides 26 channel/result checks. A native peer interleaves notifications, a server request and reversed replies; deterministic in-memory peers cover duplicate IDs, remote errors, missing payloads, malformed envelopes, EOF, deadlines, cancellation, writer backpressure and scope cleanup. Typed result tests distinguish absent, null and invalid payloads, preserve remote error precedence and verify that local decoding failure leaves the channel usable. IDs are supplied by the caller and must remain unique for the connection. The event queue has one consumer and is currently unbounded; slow-consumer overflow policy is not inferred from the reference SDKs.

Review identified two terminal-state defects in the channel: post-poison frames could still enter the event queue, and reader failure could be mislabeled as write failure during sender startup. Both regressions failed before the fixes. Dispatch checks terminal state in the same STM transaction as delivery; send-error handling preserves the recorded terminal cause without blocking cancellation.

`test/DispatchSpec.hs` adds 16 checks for the opt-in generic dispatcher: native callbacks with concurrent requests, ordered listener snapshots, idempotent removal, successor-safe handler replacement, in-flight snapshots, duplicate IDs, response identity/context, reentrant requests, redacted handler failure, terminal replay and owned-worker cleanup. Sibling-finalizer tests require concurrent cancellation rather than sequential cancellation that could deadlock. An independent read-only implementation review found no issues. All 55 process/protocol/dispatcher checks passed thirty consecutive runs with four test workers and two GHC capabilities.

`test/ClientSpec.hs` adds 130 checks for 31 statically defined local operations and 45 named request/response aliases. Every binding is checked against its schema method/response links, required parameters, result decoding, error precedence and exact outbound request. A native peer verifies model discovery and directory-change messages. Tests also protect caller metadata/extensions, omitted protocol signals, explicit deadlines and redacted configuration. All 185 process/protocol/dispatcher/client checks passed twenty consecutive parallel runs.

`MethodRequest` uses nominal method and parameter roles. Compiler probes at `/tmp/droid-method-roles.jLHLsn` accept same-type coercion and reject both method substitution and coercible parameter-wrapper substitution. These are compiler checks, not merely JSON round trips. Independent review found no issues in the new aliases and operation bindings.
